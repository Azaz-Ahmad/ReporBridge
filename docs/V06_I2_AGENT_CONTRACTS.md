# Typed contracts and review semantics

MultiRequest extends the strict RunRequest with optional decision_id. Unknown fields, patient IDs in tool arguments and malformed identifiers are rejected. The server authorizes patient and decision, reads its obligation/prerequisites and binds revision/snapshot. An unrelated decision cannot override patient scope.

A01 preserves Draft and ClinicalEvidenceReviewPacket. A02 ReconciliationDraft adds conflicting_records, corrected_records, supersession_relationships and unresolved_discrepancies. Correction IDs must have a source predecessor; supersession pairs must equal deterministic source lineage within the selected inventory. A valid lineage does not declare a record clinically authoritative.

A03 ContextDraft adds source-linked timeline events with exact clinical times, authorized obligation IDs and authorized life-stage event IDs. Times must be in chronological order. Ingestion time remains separate metadata. No outcome or clinical condition is inferred.

A04 GapDraft adds all prerequisite IDs/states/source IDs exactly as configured by the backend and targeted review questions. Missing/unavailable/conflicting/reconciliation prerequisites require abstention. Timing is added deterministically to the final packet, rather than generated by a model.

Every backend-owned AgentResult contains run/agent/patient/objective, state, findings, source refs, uncertainty, abstention, validation status, requested model, execution metadata, validated structured output and error. A02 uses run ID plus agent ID as its stable reconciliation identity. State values: not_selected, pending, running, completed, abstained, failed.

UnifiedReviewPacket extends the existing typed review packet with packet_complete, failed_agents, decision_id, timing, policy, prerequisites, agent_sections, administrative follow-up proposals and trusted context. It always requires human review. packet_complete means selected agent outputs validated; it never means clinically complete or exhaustive source retrieval.

Specialist output schema is supplied to Responses and checked again locally. Google receives the established structural-only compatibility profile; full local limits remain enforced. Findings need exact source version plus an exact excerpt or structured value. Unknown citations, wrong values, unavailable sources, unsupported clinical/timing advice, invented prerequisite states or unsupported lineage are withheld. Arbitrary narrative, even with a valid citation, remains clinician-interpreted.

Compatibility processing repairs only a raw string that exactly equals the authoritative normalized source string, by JSON-encoding that same value. It records the repair count; changed values still fail. Backend-generated support templates make the original representation explicit. Metadata-only prose is withheld rather than promoted to a clinical fact, with a recorded withheld count and uncertainty. If no supported finding remains, the agent abstains. Unknown citations and wrong versions still fail. Safety checks cover summary, findings, missing/conflicting information, uncertainty, review actions and specialist questions/discrepancies.
