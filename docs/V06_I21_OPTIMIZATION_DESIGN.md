# Increment 2.1 optimization design

The default optimized profile retains A01, A02, A03 and A04 and the seven original authoritative M08 retrieval interfaces. No agents, model routing, clinical rules or deadline policies were added. The original six-node A01 graph remains nested. The optimized supervisor has eight real nodes: validate_request, supervisor_planning, clinical_evidence_investigation, specialist_agent_routing, specialist_execution, deterministic_grounding_validation, unified_clinical_review_packet and human_review_queue. Its execution node coordinates independent read-only specialist calls rather than pretending that serial agent nodes ran concurrently.

Routing is deterministic and persisted with reasons. A02 runs for retrieved conflicts/correction lineage or configured reconciliation needs. A03 runs for an explicit longitudinal/chronology objective. A04 runs only for a missing/unavailable configured prerequisite. Failed or unvalidated A01 output prevents specialist execution. All mandatory source validation and human-review gates run even when no specialist is selected. Source chronology and configured prerequisite/timing states remain available deterministically when their specialist is skipped.

Shared context is canonical JSON in a frozen SealedContext with a digest. It contains backend-owned run/patient/authorization, source fingerprint, IDs/versions/hashes/timestamps/provenance/quality/values/excerpts/lineage, decision revision/hash/prerequisites and registered timing references. Each consumer gets a fresh decoded copy; model output cannot mutate it. Original records remain available for validation. Final fingerprint, ownership/version/hash/quality and decision-binding checks invalidate changed evidence; submission/review repeat freshness checks.

A02 receives relevant conflict/correction chains; A04 receives prerequisite-related sources; A03 receives the bounded longitudinal inventory. No LLM summary becomes authoritative evidence. Model-facing projection keeps complete structured values and source metadata while removing presentation/redundant normalization fields. Identical source payloads in conversation history become ID/version/hash references, preserving all function-call/output pairs and required Responses history. Current source semantics are never inferred from an LLM summary.

Tool interfaces retain their original typed arguments, pagination, scope enforcement, eight-result maximum and 50,000-character source-result limit. Optimized context retains at most 16 source IDs, 24,000 shared characters and 48,000 serialized input characters. A retrieved text section over 600 characters is omitted with a recorded limitation, rather than prefix-truncated. Omitted required context forces a partial/abstained packet. Complete short sections and clinical values remain exact. Raw source APIs and original records remain authoritative.

The request-local retrieval cache normalizes arguments and pins role/patient/fingerprint. Every hit rechecks authorization, canonical identity and the pinned fingerprint. Provenance and quality share entries because both original M08 implementations return the same underlying evidence read. Distinct queries are not conflated. A bounded deterministic predecessor read uses get_evidence_provenance if a retrieved correction lacks its predecessor, within the global tool budget; missing lineage remains an explicit limitation.

A01 is bounded to three model invocations; each selected specialist gets one, with the original global maximum seven and five tool requests retained. Explicit excess-call denials and final drafting are preserved. Known unsent preflight failures do not count as provider calls. No automatic retry of an unknown timeout or interrupted model call occurs. Historical/partial validated findings remain inspectable, required specialist failures make the packet partial, and partial approval is blocked. Interrupted pending/running agent states become failed rather than displaying indefinitely fabricated activity.

When enabled, independent specialists run in a bounded ThreadPoolExecutor on the same sealed snapshot. Workers perform model calls and local validation only: no SQL, M08 retrieval, clinical mutation or persistence. Call slots are reserved before dispatch; each worker has a bounded provider timeout and independent client. The coordinator serially persists actual completion events and merges in stable agent/call order. Approval, review, closure, source retrieval and all SQL persistence remain sequential. Cumulative model time can exceed elapsed time under concurrency; both are labeled separately.

Provider invocation timing, context/schema/tool-definition characters, requested/reported IDs, response IDs, retries, error classes, input source references and agent grounding are persisted without prompts or raw documents. Tool timing/response size, cache hits, source refs and final snapshot validation are recorded. Existing JSON run/review tables suffice; no migration or endpoint family was added, and Alembic head remains 0006. Progress now uses one existing run read/JSON update rather than two of each. Source/rule synchronization and transaction serialization are preserved.

MULTI_AGENT_EXECUTION_PROFILE defaults to optimized. legacy explicitly selects a frozen Increment 2 implementation for rollback and matched evaluation; it never follows a failure automatically. Its only source adjustment is redirecting the shared-module import to the matching frozen copy. Original behavior tests opt into this explicit legacy profile; additional optimization tests exercise the default path and compare both on identical disposable fixtures. Single-agent creation remains unchanged. MULTI_AGENT_PARALLEL defaults true; false supplies a measured serial control. All profiles use the configured model, Responses, unchanged strict output contracts and the existing Google structural-schema adaptation.

Protocol references: [OpenRouter stateless Responses](https://openrouter.ai/docs/api_reference/responses/overview), [LangGraph conditional routing](https://reference.langchain.com/python/langgraph/graph/state/StateGraph/add_conditional_edges). Actual SDK requests and persisted traces determine compatibility.
